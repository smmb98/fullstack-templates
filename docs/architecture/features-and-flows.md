# Feature slices and flow cards
Every feature is a self-contained slice, registered, flagged, storied, tested and documented by one card.
Read this when creating or changing a feature, its flag, its route or the generated index.

## Slice layout
`apps/shop/src/features/<id>/`
```
feature.meta.ts      defineFeature({...})
index.ts             public exports only
components/          feature components
hooks/               feature hooks
api.ts               api client calls + query keys
*.stories.tsx        one per declared state
*.test.ts(x)         unit tests
```
E2E spec at `apps/shop/e2e/<id>.spec.ts`; flow card at `docs/flows/<id>.md`.

## feature.meta.ts
`defineFeature({ id, title, flag, routes, endpoints, states, scenarios, dependsOn, tag, nav? })`
- `scenarios` maps each supported scenario to the `data-state` the primary region must show,
  e.g. `{ "error-500": "error:http" }`.
- `nav` is `{ label, href, placement }`; navigation is generated from metas + flags.
- `tag` is the Playwright grep tag (`@<id>`).

## Rules
- Features import other features only through their `index.ts`, and only if listed in
  `dependsOn`. Shared code (`packages/*`, `apps/shop/src/shared`) never imports a feature.
- Route files under `app/` are thin: render the feature page; call `notFound()` when the
  flag is off.
- Registry: `apps/shop/src/features/registry.ts` (explicit imports).
  Flags: `apps/shop/features.config.json`.
- One feature change updates meta, flag, card, stories and e2e spec together.

## Generated index
`docs/flows/INDEX.md` starts with `GENERATED by pnpm flows:gen. Do not edit.` and has one
line per feature: `id | routes | flag | states | scenarios | deps | card`.
Run `./dev pnpm flows:gen` after any meta change; never edit the file by hand (D10).

## Drift check
`flows:check` fails when:
- a meta lacks a card, or a card lacks a meta;
- a declared state has no story named `States/<State>`;
- no e2e spec carries the tag;
- a flag is missing in `features.config.json` or is orphaned;
- a route in the meta has no route file;
- `INDEX.md` is out of date;
- `dependsOn` has a cycle;
- a feature imports another feature's internals (not via `index.ts`).

## Flow cards
Use `docs/flows/_template.md`, keep the card <= 60 lines and current: purpose, user flow,
UX rules, scenario -> state table, edge cases, tests, dependencies, reduction notes.
The card is what an agent reads instead of the code; write facts, not history.

## Flags and reduction
Soft reduce = flip flags off (reversible). Hard reduce = delete slices (see
`docs/architecture/reduction.md`). A feature must be disableable by its flag alone without
breaking other features; if not, the dependency is missing from `dependsOn`.
